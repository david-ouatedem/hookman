# v0.1 — Core Delivery Pipeline

**Date:** 2026-03-17

## What was done

Implemented the full webhook delivery pipeline — from event ingestion to HTTP delivery with retries and dead-lettering.

### Components implemented

#### 1. sqlc Query Layer (`internal/store/queries/`)
- **events.sql** — CreateEvent, GetEvent, ListEvents (with topic/status/cursor filters), UpdateEventStatus, GetPendingEvents (`FOR UPDATE SKIP LOCKED`), GetEventByIdempotencyKey
- **endpoints.sql** — CRUD, GetEndpointsByTopic (uses `ANY(topics)` for array matching)
- **delivery_attempts.sql** — CreateDeliveryAttempt, GetByEvent, GetByEndpoint, GetRetryableAttempts (`DISTINCT ON` for latest per event+endpoint pair)

#### 2. Postgres Store (`internal/store/postgres.go`)
- Single `PostgresStore` struct implementing all 3 store interfaces
- Wraps sqlc-generated `Queries` with `pgxpool.Pool` for connection pooling
- Thin adapter: `GetEndpointsByTopic(topic string)` wraps sqlc's `[]string` parameter

#### 3. ID Generation (`internal/id/`)
- ULID-based IDs with prefixes: `evt_`, `ep_`, `da_`
- Cryptographic randomness via `crypto/rand`

#### 4. HTTP Delivery (`internal/delivery/deliver.go`)
- `Deliver(ctx, client, job) DeliveryResult`
- Signs payload with HMAC-SHA256, sends headers: `X-Hookman-Signature`, `X-Hookman-Event-Id`, `Content-Type`, `User-Agent`
- Captures HTTP status, response body (capped at 4KB), duration
- Returns `NextRetryAt` on failure, `nil` when exhausted (dead letter)
- Handles: 2xx success, 4xx/5xx failure, connection refused, DNS failure, timeout

#### 5. Worker Pool (`internal/worker/pool.go`)
- Fixed pool of N goroutines reading from a shared `chan DeliveryJob`
- Each worker: deliver → record attempt → update event status (delivered/dead) or leave for retry
- Graceful shutdown: context cancellation + `sync.WaitGroup`
- Backpressure: channel blocks naturally when all workers are busy

#### 6. Poller (`internal/worker/poller.go`)
- Ticker-based loop at configurable `PollInterval`
- Two polling paths:
  1. **Pending events** — queries `status = 'pending'`, matches to endpoints by topic, marks as `processing`, feeds jobs
  2. **Retryable attempts** — queries `next_retry_at <= NOW()` with `status = 'failed'`, increments attempt number, feeds jobs

#### 7. API Server (`internal/api/`)
- **Chi router** with RequestID, RealIP, Recoverer middleware
- **Auth middleware** — constant-time comparison of `Bearer` token against `API_KEY`
- **Event routes:**
  - `POST /api/events` — ingest with idempotency key support
  - `GET /api/events` — list with `topic`, `status`, `limit`, `before` cursor
  - `GET /api/events/:id` — detail with all delivery attempts
  - `POST /api/events/:id/replay` — reset status to `pending`
- **Endpoint routes:**
  - `POST /api/endpoints` — create with auto-generated `whsec_` signing secret
  - `GET /api/endpoints` — list all
  - `PATCH /api/endpoints/:id` — partial update (url, topics, description, enabled)
  - `DELETE /api/endpoints/:id` — delete
  - `GET /api/endpoints/:id/deliveries` — delivery history
- **Health:** `GET /health`

#### 8. Main Entrypoint (`cmd/hookman/main.go`)
- `serve`: connects to Postgres → creates store → starts worker pool → starts poller → starts HTTP server → graceful shutdown on SIGINT/SIGTERM
- `migrate`: uses `golang-migrate` with `file://migrations` source
- `version`: prints `0.1.0`

## Key decisions

| Decision | Rationale |
|----------|-----------|
| **sqlc types directly in interfaces** | Dropped custom domain types from v0.0 — using `queries.*` types everywhere avoids mapping boilerplate |
| **Single `PostgresStore` struct** | All 3 interfaces on one struct — same DB pool, simple to construct, can split later |
| **`file://migrations` not embedded** | Embedded FS doesn't work from `cmd/hookman/` without copying; `file://` works with standard layout |
| **Mock store for API tests** | In-memory mock implements `store.Store` — no DB needed for API handler tests |
| **`whsec_` prefix for signing secrets** | Convention from Svix — makes secrets identifiable, 32 random bytes hex-encoded |
| **Response body capped at 4KB** | Prevents memory issues from large error pages in delivery responses |
| **`FOR UPDATE SKIP LOCKED`** | Prevents multiple poller instances (future multi-instance setup) from processing same event |
| **Separate `processing` status** | Events go `pending → processing → delivered/dead` — prevents duplicate delivery on re-poll |
