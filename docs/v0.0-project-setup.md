### What's fully implemented

1. **Config loader** — reads all env vars from the spec with defaults, validates required vars
2. **HMAC-SHA256 signing** — `Sign()` and `Verify()` with constant-time comparison
3. **Retry backoff schedule** — matches spec (30s, 5m, 30m, 2h, 5h)
4. **CLI entrypoint** — `serve`, `migrate`, `version` subcommands
5. **Database migrations** — 3 migration files matching the data model spec
6. **Store interfaces** — `EventStore`, `EndpointStore`, `DeliveryStore` contracts
7. **Docker setup** — Compose with Postgres health check, multi-stage Dockerfile

## Key decisions

| Decision | Rationale |
|----------|-----------|
| **Chi router** (planned) | Lightweight, idiomatic Go, uses `net/http` interfaces |
| **pgx/v5** for Postgres | Pure Go driver, best performance, pgx is the modern standard |
| **sqlc** for queries | Type-safe generated code from raw SQL, no ORM surprises |
| **ULID IDs** (planned) | Time-sortable, better for pagination than UUID |
| **golang-migrate** for migrations | Industry standard, supports up/down, CLI and library |
| **slog** for logging | stdlib structured logging, JSON output, no external dependency |
| **Store interfaces** | Allows swapping Postgres for Redis/MySQL later |
| **Backoff in code, not config** | Fixed schedule per spec; simpler than configurable for v0 |
