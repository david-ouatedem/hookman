# v0.2 — Management API + Dead Letter + Metrics

**Date:** 2026-03-18

## What was done

Added dead letter queue management, event statistics, and Prometheus metrics instrumentation.

### Dead Letter Queue Management

Three new API endpoints for managing failed events:

| Endpoint | Description |
|----------|-------------|
| `GET /api/events/dead` | List dead-lettered events (paginated with `limit` and `before` cursor) |
| `POST /api/events/dead/replay` | Bulk replay: reset all dead events back to `pending` |
| `DELETE /api/events/dead` | Purge: permanently delete all dead events |

**sqlc queries added:**
- `GetDeadEvents` — `WHERE status = 'dead'` with cursor pagination
- `BulkReplayDeadEvents` — `UPDATE ... SET status = 'pending' WHERE status = 'dead'`
- `PurgeDeadEvents` — `DELETE FROM events WHERE status = 'dead'`

### Event Statistics

| Endpoint | Description |
|----------|-------------|
| `GET /api/stats` | Aggregate event counts by status (`pending`, `processing`, `delivered`, `failed`, `dead`, `total`) |

**sqlc query added:**
- `CountEventsByStatus` — `SELECT status, COUNT(*) FROM events GROUP BY status`

### Prometheus Metrics

Enabled via `METRICS_ENABLED=true`, exposed at `GET /metrics` (no auth required).

| Metric | Type | Labels | Description |
|--------|------|--------|-------------|
| `hookman_events_total` | Counter | `topic` | Events ingested |
| `hookman_delivery_attempts_total` | Counter | `status` | Delivery attempts (success/failed) |
| `hookman_delivery_duration_seconds` | Histogram | `status` | Delivery duration distribution |
| `hookman_queue_depth` | Gauge | `status` | Current queue depth per poll cycle |
| `hookman_dead_letter_total` | Counter | — | Events moved to dead letter queue |

**Instrumentation points:**
- Event creation → `RecordEventCreated(topic)`
- Worker delivery attempt → `RecordDeliveryAttempt(status, durationMs)`
- Worker dead-lettering → `RecordDeadLetter()`
- Poller cycle → `RecordQueueDepth("pending", count)`

## Key decisions

| Decision | Rationale |
|----------|-----------|
| **`/metrics` without auth** | Standard Prometheus convention; scraping shouldn't need API keys |
| **`/metrics` conditionally mounted** | Only registered when `METRICS_ENABLED=true` — zero overhead when disabled |
| **`promauto` for metric registration** | Auto-registers with default registry, avoids boilerplate |
| **Histogram buckets (50ms–10s)** | Covers typical webhook delivery range; fast local + slow remote endpoints |
| **`execrows` for bulk operations** | Returns affected row count for replay/purge — useful for API response |
| **Dead letter routes before `{id}` routes** | Chi trie router handles this correctly (literal > param), but grouped for clarity |
| **Queue depth from poll batch size** | Approximation per poll cycle, not exact count — avoids extra COUNT query |

## API summary (v0.2)

```
GET    /health                        # liveness check (no auth)
GET    /metrics                       # Prometheus metrics (no auth, opt-in)

POST   /api/events                    # ingest event
GET    /api/events                    # list events (filters: topic, status, limit, before)
GET    /api/events/:id                # event detail + delivery attempts
POST   /api/events/:id/replay         # replay single event
GET    /api/events/dead               # list dead-lettered events
POST   /api/events/dead/replay        # bulk replay all dead events
DELETE /api/events/dead               # purge all dead events

POST   /api/endpoints                 # create endpoint
GET    /api/endpoints                 # list endpoints
PATCH  /api/endpoints/:id             # update endpoint
DELETE /api/endpoints/:id             # delete endpoint
GET    /api/endpoints/:id/deliveries  # delivery history

GET    /api/stats                     # event counts by status
```
