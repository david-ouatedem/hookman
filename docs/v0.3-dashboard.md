# v0.3 — Dashboard (HTMX + Go Templates)

**Date:** 2026-03-18

## What was done

Built a server-rendered dashboard using Go `html/template` + HTMX + Pico CSS. No Node.js, no build step — templates are embedded in the binary via `//go:embed`.

### Architecture change

Replaced the planned React dashboard (`dashboard/` directory) with HTMX-powered Go templates at `internal/dashboard/`. This keeps the entire project in Go with zero frontend tooling.

### Pages

| Route | Page | Features |
|-------|------|----------|
| `GET /dashboard` | Stats overview | Event counts by status (pending, processing, delivered, dead, total), bulk replay button for dead events |
| `GET /dashboard/events` | Events list | Filter by topic and status (HTMX live filter), cursor pagination, replay button per event |
| `GET /dashboard/events/:id` | Event detail | Full payload (formatted JSON), status badge, replay button, delivery attempts table |
| `GET /dashboard/endpoints` | Endpoints management | Create form (collapsible), enable/disable toggle, delete with confirmation |

### HTMX interactions

- **Filter events** — form `hx-get` swaps table body without full page reload
- **Replay event** — `hx-post` shows toast notification
- **Bulk replay dead** — `hx-post` replays all dead events, shows count in toast
- **Create endpoint** — `hx-post` form submits, re-renders endpoint table
- **Toggle endpoint** — `hx-post` toggles enabled/disabled, swaps table
- **Delete endpoint** — `hx-delete` with `hx-confirm` dialog, swaps table

### HTMX partials

| Route | Returns |
|-------|---------|
| `GET /dashboard/partials/events` | Event table rows (for filter/pagination) |
| `GET /dashboard/partials/endpoints` | Endpoint table rows (for CRUD updates) |

### Template structure

```
internal/dashboard/
├── dashboard.go                  # Handler, routes, template helpers
├── dashboard_test.go             # 6 tests
└── templates/
    ├── layout.html               # Base layout (Pico CSS + HTMX CDN, nav)
    ├── stats.html                # Dashboard home
    ├── events.html               # Events list + filter form
    ├── event_detail.html         # Event detail + delivery attempts
    ├── endpoints.html            # Endpoints list + create form
    └── partials/
        ├── event_rows.html       # Event table body fragment
        ├── endpoint_rows.html    # Endpoint table body fragment
        └── toast.html            # Success/error notification
```

### Template helpers

| Helper | Purpose |
|--------|---------|
| `formatTime` | Formats `pgtype.Timestamptz` to `2006-01-02 15:04:05` |
| `statusClass` | Maps status to CSS class (success/pending/failed/dead) |
| `formatJSON` | Pretty-prints JSON payload |
| `joinTopics` | Joins `[]string` with commas |
| `derefInt32` | Safely renders nullable `pgtype.Int4` |
| `derefText` | Safely renders nullable `pgtype.Text` |

## Key decisions

| Decision | Rationale |
|----------|-----------|
| **HTMX + Go templates instead of React** | No Node.js build step, no npm, entire project stays in Go. Simpler deployment — single binary |
| **Pico CSS (CDN)** | Classless CSS framework — clean look with zero custom CSS effort. ~10KB |
| **HTMX 2.0 (CDN)** | Minimal JS, server-driven interactions. Perfect for admin dashboards |
| **`//go:embed` for templates** | Templates compiled into binary — no file system dependency at runtime |
| **No auth on dashboard** | Same as `/health` and `/metrics` — internal tool, protected by network policy |
| **`DASHBOARD_ENABLED` flag** | Can disable in production if dashboard is not needed |
| **Partials pattern** | HTMX swaps table body only — avoids full page reloads for filter/CRUD |
| **Toast notifications** | Lightweight feedback for actions (replay, create, delete) — auto-fades after 3s |
